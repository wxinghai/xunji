# 01 数据模型

现有 `common/types.uts` 是简版。本章列出**必须扩展的字段**，全部来自 APK 真实结构，扩展后仍能向后兼容已存的 `xunji_records_v1` 数据（新字段给默认值即可）。

## 1. Movement（动作）

现有定义**已经够用**，无需改动。`static/moves.json` 里 1,062 条都带完整字段：

```ts
export type Movement = {
	id : string            // "10431201"
	name : string          // "负重颈弯举"
	category : string      // "颈部"
	exetype : string       // weight | cardio | times | record | plus_weight | help | stretch | tabata
	aliases : string[]     // 含中文别名、英文名、id 本身
	primary : string[]     // ["胸大肌","三角肌前束"]，1,003 条有值
	secondary : string[]   // ["上胸","肱三头肌"]
	section : string       // selfweight | dumbell | barbell | cable | machine | hammer | smithmachine | kettle_bell | trxband | other
	classes : string[]     // 器械可用性，多值
	bodyweight_only : boolean
	load_type : string     // external_load | bodyweight | ...
	home_friendly : boolean
}
```

**注意** `section` 有拼写陷阱：原数据里同时存在 `dumbell`（133 条，正确用词但拼写错）和 `dumbbell`（1 条）。`common/moves.uts` 的 `SECTION_LABELS` 两个都映射了，**不要删任何一个**。

新增字段（可选，本次不做）：`detailDesc`（视频讲解文案，1,220 条有）、`moreMP4`（多角度视频名）。若要显示卡片左上角的"视频讲解"角标，按 `detailDesc` 是否非空判断即可 —— 但本项目不放 mp4，**建议直接不做这个角标**。

## 2. TrainSet（一组）

现有：
```ts
export type TrainSet = {
	weight : number
	reps : number
	seconds : number
	done : boolean
}
```

APK 原结构（模块 4382 + 472）：

| 字段 | 类型 | 说明 | 本次是否要 |
|---|---|---|---|
| `weight` | number | 重量 | ✅ 已有 |
| `reps` | number | 次数 | ✅ 已有 |
| `seconds` | number | 计时类动作的秒数 | ✅ 已有 |
| `done` | boolean | 完成勾选 | ✅ 已有 |
| `setType` | string | `"热"` = 热身组，不计入容量 | ⭐ **要加** |
| `unit` | string | `"kg"` / `"lbs"`，**逐组独立** | ⭐ 要加 |
| `left_weight` | number | 单侧动作的左/右重量 | 可选 |
| `rpe` | number | 自觉强度 1–10 | 可选 |
| `dropset` | DropSet[] | 递减组 `{weight,reps,left_weight}` | 不做 |
| `performTime` | number | 实际完成时刻 | 不做 |

**最小改动**：在 `TrainSet` 加两个字段，给默认值：

```ts
export type TrainSet = {
	weight : number
	reps : number
	seconds : number
	done : boolean
	setType : string     // '' 普通 | '热' 热身
	unit : string        // 'kg' | 'lbs'
}
```

`newMove()` 里初始化成 `setType: ''`、`unit: 'kg'`。旧数据读进来这两个字段是 `null`，读取时按 `''` / `'kg'` 兜底。

### 为什么 `unit` 要逐组存

原 App 允许一组 kg 一组 lbs（模块 471 的 `Calulator` 里 `k = "kg" === f ? 1 : .4532` 是**逐组**算的）。若只在设置里存全局单位，换算会错。本次若不做单位切换，`unit` 恒为 `'kg'`，但**字段先留着**，以后加设置项不用改数据结构。

## 3. TrainMove（训练中的一个动作）

现有：
```ts
export type TrainMove = {
	key : string
	name : string
	category : string
	exetype : string
	section : string
	sets : TrainSet[]
}
```

APK 原结构额外有：

| 字段 | 说明 | 本次 |
|---|---|---|
| `restTime` | 组间休息秒数（默认 90） | ⭐ 要加 |
| `warn_restTime` | 热身组休息秒数（默认 45） | 可选 |
| `oneSide` | 单侧动作，容量 ×2 | ⭐ 要加 |
| `superset` | 超级组，`moves[][]` 嵌套 | 不做 |
| `currentWeight` | 自重动作用的体重 | 可选 |
| `barWeight` / `barUnit` | 杠铃杆重 | 不做 |
| `note` | 该动作备注 | 可选 |

**最小改动**：

```ts
export type TrainMove = {
	key : string
	name : string
	category : string
	exetype : string
	section : string
	sets : TrainSet[]
	restTime : number    // 秒，默认 90
	oneSide : boolean    // 默认 false
}
```

`oneSide` 在 `moves.json` 里没有现成字段 —— 原 App 从 `movementMap[key].oneSide` 读，该字段在模块 472 的 catalog 里但未导出到 `moves.json`。**本次简化**：`oneSide` 恒 `false`，字段先留着。

## 4. TrainRecord（一条训练记录）

现有：
```ts
export type TrainRecord = {
	id : string
	date : string        // "YYYY-MM-DD"
	title : string
	note : string
	start : number       // ms 时间戳
	end : number
	moves : TrainMove[]
}
```

APK 的 `localtrains` 表（20 张表之一）额外有 `color`、`templateid`、`types[]`、`duration`、`calories`。本项目**都不需要**，现有结构够用。

⚠️ 一个隐患：现有 `newRecord()` 里 `date: ''` 是空字符串，靠调用方填。**所有读记录的地方都要防 `date == ''`**，否则 `localeCompare` 和日历聚合会出问题。建议在 `newRecord()` 里直接写 `date: todayKey()`。

## 5. 存储键

现有 2 个 key，够用：

| Key | 内容 | 位置 |
|---|---|---|
| `xunji_records_v1` | `TrainRecord[]` JSON | `common/storage.uts` |
| `xunji_active_v1` | 当前未完成的 `TrainRecord` | 同上 |

新增 1 个（可选）：

| Key | 内容 |
|---|---|
| `xunji_settings_v1` | `{ unit: 'kg'\|'lbs', firstDayOfWeek: 0\|1, restTime: 90, warmupRest: 45 }` |

**体积警告**：`uni.setStorageSync` 在 App 端基于原生 KV，单 key 几 MB 没问题，但**每次 `saveRecords` 都全量序列化**。1,000 条训练记录约 2–3 MB，届时需要改成分片。本次不做。

## 6. 数据迁移

目前没有真实用户数据，**不需要迁移逻辑**。若将来加字段，读取时用"缺省兜底"而不是版本号判断：

```ts
const set = raw as TrainSet
return {
	weight: set.weight,
	reps: set.reps,
	seconds: set.seconds,
	done: set.done,
	setType: set.setType == null ? '' : set.setType,
	unit: set.unit == null ? 'kg' : set.unit
} as TrainSet
```
