## 2. gif-map.json —— 主查表

**格式**：扁平对象，key 是动作 id，value 是相对 `static/` 的路径。

```json
{
  "10431201": "gifs/10431201_10431201.gif",
  "13001201": "gifs/13001201_13001201-Lever-Decline-Chest-Press_Chest_.gif"
}
```

**用法**（动作卡片和详情页都走这个）：

```ts
import gifMap from '@/static/gif-map.json'

export function gifOf(moveId : string) : string {
	const v = (gifMap as UTSJSONObject).getString(moveId)
	return v == null ? '' : ('/static/' + (v as string))
}
```

返回空字符串时显示文字占位（原 App 也这么做，见模块 4747：`l.uri ? <Image> : <View 圆形><Text>{name[0]}</Text>`）。

## 3. gif-index.json —— 完整索引

**格式**：数组，每行一个动图。

```json
{
  "moveId": "10431201",          // 空字符串 = 该动图不对应库内任何动作
  "name": "负重颈弯举",
  "file": "10431201_10431201.gif",
  "via": "name"                  // name | alias:xxx | override:xxx | gif-only
}
```

用途：动作详情页底部的"相关动图"、以图搜动作。**本次三 Tab 不需要，先不用读它**。加载它反而浪费内存（152 KB JSON）。

### 行数与文件数为什么对不上

| 值 | 含义 |
|---|---|
| 1,271 行 | 索引条目 |
| 1,230 | 磁盘上的唯一 GIF 文件 |
| 1,052 | 有 `moveId` 的行（对应库内动作） |
| 219 | `moveId` 为空的 gif-only 行 |

差值 41 是**两个动作共用同一张动图**（如某个动作有多个别名条目指向同一个文件）。`gif-map.json` 按动作 id 建表，不受影响。

## 4. GIF 文件规格

- 格式：GIF87a/GIF89a，**已确认 uni-app x `<image>` 可直接渲染**
- 尺寸：多数 480×270，少数 360×360
- 体积：平均 167 KB，中位数 122 KB，最大 1.3 MB
- 文件名：纯 ASCII，无空格，含 `()` 的 102 个 —— Android 打包没问题，**不要重命名**

### 内存提示

204 MB 全量打包进 APK 会让安装包变大。若在意体积，可以只保留 `gif-map.json` 里引用的文件（**1,011 个唯一文件**，1,052 个动作共用）。当前 1,230 个文件中，219 个是 gif-only（不对应库内任何动作）。

**建议先全量保留**，跑通后再裁剪。
