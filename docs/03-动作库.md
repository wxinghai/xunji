> 原 App 模块：`4745`（页面容器）· `4747`（卡片 `MovementItem`）

## 0. 当前实现 vs 原版：三个结构性差异

| 差异 | 现在 | 原版 | 处理 |
|---|---|---|---|
| 列表形态 | 单列横向长条（`list-item` 一行一个） | **双列卡片网格** | ⭐ 必改 |
| 图标 | 分类首字文字 | **70×70 圆形 GIF** | ⭐ 必改 |
| 二级分类位置 | 列表上方横向 chip | **左侧栏内、一级分类下方缩进** | ⭐ 必改 |

## 5. 卡片网格（模块 4747）

### 5.1 尺寸计算

```ts
const cardW = (W - 96 - 24) / 2
```

- `96` = 侧栏 88 + 右边距 8
- `24` = 网格左侧 padding 8 + 卡片间距 8 + 右侧留白 8

以 360dp 宽屏为例：`(360 - 120) / 2 = 120`。

uni-app x 里没有可靠的运行时屏宽变量，用 `uni.getWindowInfo().windowWidth` 计算：

```ts
const W = uni.getWindowInfo().windowWidth
const cardW = (W - 120) / 2
```

### 5.2 卡片本体

```
TouchableOpacity: {
  padding: 8,
  backgroundColor: selected ? THEME_COLOR : (dark ? THEME_BK_LIGHT : THEME_BK_LIGHTER),
  marginLeft: 8, marginBottom: 8,
  borderRadius: 16,
  position: 'relative',
  width: (W-96-24)/2,
  alignItems: 'center',
  overflow: 'hidden'
}
```

浅色主题下 `THEME_BK_LIGHTER = white`（`#FFFFFF`），深色主题为 `#46454b`。

### 5.3 卡片内的元素

| 元素 | 样式 | 条件 |
|---|---|---|
| 动图 | `width:70 height:70 borderRadius:35` | 有 gif 时 |
| 文字占位 | `width:70 height:70 borderRadius:40 borderWidth:1 borderColor:T_COLOR()`，内含 `fontSize:24 fontWeight:'bold'` 的首字 | 无 gif 时 |
| 名称 | `color:T_COLOR() textAlign:'center' lineHeight:16.8 fontSize:14`，外层 `{flex:1, marginTop:8}` | 总是 |
| 视频角标 | `backgroundColor:THEME_COLOR, padding:4, paddingLeft:6, paddingRight:6, position:'absolute', left:0, borderBottomRightRadius:6, zIndex:10000000`，文字 `fontSize:8 fontWeight:'bold' color: white/black` | 有 `detailDesc` 时 |
| 次数角标 | `paddingVertical:4, position:'absolute', right:8, top:2`，文字 `color:T_COLOR(.3) fontSize:10 fontWeight:'bold'` | 该动作有历史次数时 |

⚠️ 名称的 `lineHeight: 16.8` 配默认 `fontSize: 14` 是原码原值（RN 默认字号 14）。**不要**改成 16。

## 6. 实现建议（uni-app x）

### 6.1 为什么用 `list-view` 而不是 `scroll-view` + `v-for`

1,062 条动作，全量渲染会卡。`list-view` / `list-item` 有原生复用。但 **`list-view` 不支持双列网格**。

两个方案：

**方案 A（推荐）**：`list-view` + `list-item` 里再套一层 `view`，每行放两个卡片。即把数据每 2 条切一行：

```ts
const rows = computed<Movement[][]>(() : Movement[][] => {
	const src = filtered.value
	const out : Movement[][] = []
	for (let i = 0; i < src.length; i += 2) {
		const pair : Movement[] = [src[i]]
		if (i + 1 < src.length) { pair.push(src[i + 1]) }
		out.push(pair)
	}
	return out
})
```

模板：

```vue
<list-view class="grid" direction="vertical" show-scrollbar="false">
	<list-item v-for="(row, ri) in rows" :key="ri" class="grid-row">
		<view class="card" v-for="m in row" :key="m.id" :style="cardStyle" @tap="openMove(m.id)">
			<image v-if="gifOf(m.id).length > 0" class="card-img" :src="gifOf(m.id)" mode="aspectFit" />
			<view v-else class="card-ph"><text class="card-ph-text">{{m.name.substring(0,1)}}</text></view>
			<text class="card-name">{{m.name}}</text>
		</view>
	</list-item>
</list-view>
```

**方案 B（更简单）**：`scroll-view` + `v-for`，先只渲染前 100 条，滚动到底再追加。实现更简单，但体验不如 A。

**先做 A**。若 `list-item` 内嵌两个卡片出现布局问题（uni-app x 的 `list-item` 会强制撑满宽度），退到方案 B。

### 6.2 `cardStyle` 不能写在 CSS 里

卡片宽度是运行时算的，必须用内联 `:style`：

```ts
const cardStyle = computed<string>(() : string => {
	return 'width:' + ((W - 120) / 2).toString() + 'px;'
})
```

uni-app x 的 `:style` 接受字符串，**不要传对象**（UTS 对对象样式支持有限）。

### 6.3 GIF 加载

`<image>` 默认 `mode="scaleToFill"` 会把 480×270 的动图拉变形。**必须写 `mode="aspectFit"`**，配合 `border-radius: 35px` 裁成圆形（原版就是这么做的，GIF 本身不是圆的）。

### 6.4 搜索

现有 `searchMoves()` 是 `includes` 过滤，能跑。若要更接近原版（Fuse.js 加权），按这个权重打分排序：

| 字段 | 权重 |
|---|---|
| 官方名称精确匹配 | 5.0 |
| `name` 包含 | 2.0 |
| `equipment` 包含 | 1.8 |
| `name` 模糊 | 1.5 |
| `aliases` 包含 | 0.8 |
| `misspellings` | 0.7 |
| 英文名 | 0.6 |
| 派生词 | 0.5 |
| `primary`/`secondary` 肌群 | 0.3 |

**建议**：保持现有 `includes` 即可，先把界面做对。搜索算法优化是 P2。

## 7. 动作详情页（`pages/movement/detail.uvue`）

原版详情页是底部弹层（`5700`），不是独立页面。现有实现是独立页面 —— **可以接受**，不用改成弹层。

需要补的：**顶部放 GIF**。

```
<image :src="gifOf(moveId)" class="detail-gif" mode="aspectFit" />
```
```css
.detail-gif { width: 100%; height: 220px; background-color: #FFFFFF; }
```

原版详情页还有"动作要点"长文（`detailDesc`），本项目 `moves.json` 里没有这个字段，**跳过**。
